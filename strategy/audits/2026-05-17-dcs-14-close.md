## What changed since v3

The v3 audit credited the project for shipping two of Brunson's three canonical patterns from DCS Chapter 14 (the survey-funnel-evolved forward squeeze at `/diagnostic`, the reverse squeeze at `/parables`) and the right architectural choice that both routes feed the same Day 0 Soap Opera. The 10-point gap was honestly attributable to two things the audit did not call out explicitly:

1. **The third canonical pattern was missing.** DCS Chapter 14 teaches three squeeze archetypes, not two. The third is the canonical Brunson Lead Squeeze: one hook, one field, one CTA, zero scroll, designed for cold ad traffic / X bios / podcast call-outs / Indie Hackers reply links — anywhere additional clicks kill conversion. The project had both depth-trade squeezes (survey + reverse) but no zero-friction forward squeeze.

2. **Per-source squeeze conversion was not measurable.** All three doors (well, two pre-fix) wrote into the same `soap_opera_subscribers` table distinguished by the free-form `source` column, but no read shape existed to compare opt-in rate per surface. The Friday Audible Call had no place to read "which squeeze is converting per visitor?" — which is the question that decides which door deserves more cold traffic next week.

Both gaps are now closed.

## Shipped (autonomous push)

### 1. `/start` — canonical Brunson Lead Squeeze

**Route:** `app/src/app/(marketing)/start/page.tsx` + `fast-lane-form.tsx`.

**What it is.** Single-hook, single-field, single-CTA squeeze. The page is statically rendered (`force-static`); the form is a client island. Same headline-as-argument structure DCS Chapter 14 prescribes: if the hook does not earn the email by itself, no body copy under it will save the page.

**Brunson canon checks:**

| Chapter 14 rule | `/start` implementation |
|---|---|
| One hook | Hook #3 (the pain mirror) compressed: "You shipped it. They said they loved it. Stripe is still flat." |
| One field | Email only. No name field, no phone field, no role dropdown. |

**Where it gets used.** This is the canonical URL to paste in any context where the click count must be one: X bios, podcast show notes, Indie Hackers reply links, paid ad destinations (Phase 2), founder DM signatures, Slack profile links. The dream-100 outreach kit (`strategy/dream-100-outreach.md`) can swap any context-appropriate `/diagnostic` link for `/start` when the surface is bio-style rather than thread-style.

### 2. Per-source measurability

**File:** `supabase/views/squeeze_conversion.sql` — four read-only views.

| View | Purpose | Read recipe |
|---|---|---|
| `squeeze_conversion__per_source_daily` | Per (squeeze_family, squeeze_source, day) — opt-ins, status mix, 24h retention proxy across trailing 90 days. The detail table. | Trend + audit |
| `squeeze_conversion__per_family_weekly` | Per (squeeze_family, week) — single-row-per-family rollup. **The Friday Audible Call screen.** | `select * from public.squeeze_conversion__per_family_weekly where week >= date_trunc('week', now() - interval '4 weeks') order by week desc, opt_ins desc;` |
| `squeeze_conversion__parables_placement_split` | Per (placement, week) — mid-content vs end-content opt-ins on `/parables`. The drill-down. | Tells you if readers bounce before parable 5 |
| `squeeze_conversion__per_source_to_starter` | Per squeeze_family — opt-ins, starter purchases, core starts, pct conversion. **The downstream-revenue leading indicator.** | Decides which surface deserves more traffic next week |

**One classification rule across all four views.** Source-to-family mapping is centralized:
- `free_diagnostic*` → `survey_funnel`
- `reverse_squeeze_parables*` → `reverse_squeeze`
- `fast_lane_squeeze` → `fast_lane_squeeze`
- `funnel_hub` → `funnel_hub`
- `founding*` → `founding_waitlist`
- everything else → `other_or_legacy`

No view-fragmentation risk if a future opt-in surface lands; the classification rule sits in the views' own `case` blocks, identical across all four.

### 3. Analytics taxonomy extension

**File:** `app/src/lib/analytics/events.ts` — added `FastLaneSqueezeViewed` + `FastLaneSqueezeSubmitted` with source-attribution comment so future PostHog dashboards know the link between PostHog event name, `soap_opera_subscribers.source` value, and the SQL view family.

The Brunson-canon discipline: every new conversion surface must be added to the canonical event taxonomy file in the same commit that ships the surface. Otherwise the funnel-metrics report fragments into ad-hoc strings ("fastlane_submitted", "fast-lane-opt-in", "FastLaneOptin") within two weeks. One file. One contract.

## What stays out of scope (and stays the right call)

- **No exit-intent modal.** DCS Chapter 14 is about squeeze SURFACES; exit-intent is a growth-hacking pattern (closer to TS Secret #19 / Butterfly Marketing). Adding one to `/parables` or `/start` would conflict with the polarity-AGAINST disqualifier rule — "filter the wrong reader BEFORE asking" beats "ambush them as they leave."
- **No popup squeeze on `/` (the funnel hub).** Same reason. The homepage already has a `<NewsletterSignup />` block plus three CTA paths to `/diagnostic`, `/starter`, and `/machine-sales` per the audit's "23 Building Blocks" close. Adding a popup squeeze would be a fourth surface competing for attention with the existing three honest doors.
- **No name field on `/start`.** Brunson Chapter 14 explicitly: one field, not two. Personalization in the Soap Opera Sequence is built off the email's local-part already (`hi {first_name(email)}`) and remains accurate without a name field. Friction kills cold-traffic conversion; the name field is the single most common cause.
- **No fake countdown on `/start`.** Skeptic-avatar polarity rule (workbook 07 §3 Closes Category 4). The only scarcity in the system is the structurally-enforced Founding Cohort 50-seat cap, and that lives on `/founding`, not on the cold squeeze surface.
